## 0. Resumen en una línea

El checklist pasó de una pantalla monolítica a un **hub** (Documentos / Vehículos → lista →
detalle por documento con preview y reemplazo), el panel bloquea el veredicto ya dado, y el
pago del alta permite **prepagar N semanas** sin doble cobro de membresía.

## 1. App (`edv-route-mobile`)

### Navegación del checklist (hub)
- Eliminado el monolito `checklist_screen.dart`. Nuevos: `checklist_hub_screen.dart` (hub, posee
  el controller), `documents_list_screen.dart`, `document_detail_screen.dart`,
  `vehicles_list_screen.dart`, `vehicle_detail_screen.dart`, y
  `presentation/widgets/checklist_widgets.dart` (badges, tarjetas, filas, cajas compartidas).
- **Controller elevado**: un único `ChecklistController` creado en el hub y pasado por
  constructor a todas las sub-pantallas (un solo `GET /me/checklist`).
- `domain/entities/checklist.dart`: getters de conteo para las tarjetas del hub
  (`driverApproved`, `driverActionable`, `vehiclesActionable`, `vehicleCount`, …) y
  **`canUpload = !isApproved`** (se puede reemplazar el archivo hasta que lo aprueben; solo
  aprobado queda bloqueado).

### Preview del documento subido
- `document_detail_screen.dart`: imagen inline con `Image.network` (se **precarga** con
  `precacheImage` para un solo loading, centrado en el recuadro); **PDF** se abre con el visor
  del sistema (`url_launcher`, dependencia nueva; `AndroidManifest.xml` ganó el `<queries>` de
  `https`). URL firmada de 60 s → botón "Recargar" si expira.
- Requiere el endpoint nuevo del backend (ver §2).

### Recarga automática del estado
- `checklist_hub_screen.dart` implementa `WidgetsBindingObserver`: al **reanudar la app** o
  hacer **pull-to-refresh**, consulta `GET /me`; si ya no es `applicant` (aprobado/rechazado),
  navega a `DriverRootScreen` (pago/estado). El chofer ya no tiene que cerrar sesión.

### Pago del alta con adelanto de semanas (Forma A)
- `alta_payment_screen.dart`: selector de semanas (mín. 1) + total dinámico; desglose
  consolidado **"Membresía + Tarifa semanal × N"** (la N coincide con el selector).
- `alta_debt.dart`: `weeklyTariffUsd` (deriva la tarifa del desglose). `submitPayment` /
  `AltaPaymentController.submit` / repo: parámetro `weeks` → se envía como `periods`.

### Correo
- Confirmado **opcional** en todo el stack (app + servidor). No requirió cambios.

### Tests (16/16 verdes)
- `widget_test.dart` reescrito para renderizar la pantalla de selección directamente (el
  arranque en `SplashScreen` hacía red y dejaba el test colgado en el spinner).
- Goldens regenerados (baseline en la máquina de Luis; sensibles al entorno).
- Nuevo `test/checklist_test.dart` (11 casos): ancla las reglas de dominio, sobre todo
  `canUpload` (reemplazo permitido salvo aprobado), `needsAction` y los conteos del hub.

## 2. Backend (`edv-route-backend`) — DESPLEGADO a prod (Railway)

- **`b6f1a34`**: **Forma A**. El pago `debt` de la app acepta `periods` (total de semanas ≥1):
  cubre la deuda base (membresía + 1 semana) + `periods−1` semanas extra. Las extra se crean
  **PAGADAS al aprobar** el recibo (`enrollment.addPaidAltaWeeksOnClient`), NO al registrarlo —
  así un **rechazo no deja deuda fantasma** — con `period NULL` para anclarse junto a la base al
  «Establecer inicio». Sin doble cobro de membresía; reversión limpia vía `reverseReceipt`.
  Docs al día: `docs/api/endpoints.md` + `docs/decisions/decisions-log.md` (2026-08-14).
